## Раунд 2 (ревизия от 2026-08-31) — исправлено в `fix/review-round2`

### #12 Чекбокс «Show full names» не работал — `app/pages/home.py` `update_labels`
**Причина (уточнено при бразузерной проверке)**: Output объявлен списком
`[Output("coauthorship-graph", "stylesheet")]`, поэтому Dash ждёт ответ списком из
одного элемента. Возврат плоского списка стилей напрямую (`return updated_stylesheet`)
Dash трактует как 2 значения для 1 выхода → `SchemaLengthValidationError` → 500 →
чекбокс молча не работал. Дополнительно `STYLESHEET.copy()` — поверхностная копия:
правка label/font-size мутировала глобальную константу (после включения и перехода
по страницам граф рисовался с полными именами при выключенном чекбоксе).
**Исправлено**: `copy.deepcopy` + возврат `[updated_stylesheet]` (Dash сам распакует
внешний список, клиент получит плоский stylesheet). Проверено в Chrome: 500 нет,
клиент получает `label: "data(full_name)"`.

### #13 Статистика главной учитывала соавторские работы N раз — `app/pages/home.py` `update_graph`
**Причина**: `total_papers`/`total_citations` считались как сумма по узлам-авторам:
273 уникальные работы показывались как 771, цитирования 1 551 → 4 467.
**Исправлено**: `_graph_stats()` — уникальные публикации по узлам графа.

### #14 ETL молча терял данные при транзиентных ошибках API — `app/etl.py`
**Причины**: `get_author_id` без retry (timeout/SSL/429/5xx выкидывал автора из прогона),
пропущенный автор НЕ считался в `total_failed` (records_failed=0 при неполных данных);
`get_author_works` обрывался на первой ошибке — остальные страницы работ терялись.
**Исправлено**: retry (3 попытки с задержкой) в обоих функциях, `get_author_works`
возвращает `(works, complete)`, неполные загрузки и ненайденные авторы считаются
в `total_failed`. Проверено на живом OpenAlex: все 8 авторов, все работы, 0 ошибок.

### #15 Однофамильцы-дубли могли выбрать не тот профиль — `app/etl.py` `get_author_id`
**Причина**: в OpenAlex два профиля «Alexander Krylatov» (71 и 1 работа); брался первый
по релевантности. **Исправлено**: среди точных совпадений имени выбирается профиль
с наибольшим `works_count` (+ `per-page: 50`, чтобы точное имя не терялось за топ-25).
Проверено: всегда `A5029315125` (71 работа).

### #16 Соединения с БД не закрывались — `app/etl.py` и все страницы
**Причина**: `with sqlite3.connect(...) as conn:` коммитит, но НЕ закрывает соединение;
`run_etl` открывал соединение на каждую работу. **Исправлено**: добавлен `db_session()`
(contextmanager: commit/rollback/close) и заменены все `get_connection`.
